# Поэтапная разработка CafeGo

История создана последовательными реальными изменениями, а не разбиением
готового проекта задним числом. Точные SHA смотрите через
`git log --oneline --reverse`. Коммиты ниже идентифицируются стабильными темами.
После документации могут идти исправления, найденные при проверке; они также
сохранены отдельными коммитами.

Для изучения этапа используйте `git show <SHA>` и `git show <SHA>:путь/к/файлу`.
Для экспериментов на старом этапе создайте отдельный worktree:

```powershell
git worktree add ..\CafeGo-study <SHA>
```

Это не переключит и не перезапишет вашу рабочую копию. Первые этапы —
промежуточные состояния; полный функциональный запуск относится к итоговой версии.

## 1. `chore: initialize Go project`

Файлы: `go.mod`, `.gitignore`, `cmd/cafego/main.go`.
Создан модуль и точка входа-заглушка, исключены рабочая база и бинарник.
Проверка этапа: `go run ./cmd/cafego` выводит сообщение об инициализации.

## 2. `feat: add SQLite schema and atomic demo seed`

Файлы: `go.mod`, `internal/store/schema.sql`, `internal/store/store.go`.
Добавлены SQLite-драйвер и bcrypt как зависимости, все таблицы, ограничения,
внешние ключи и атомарное начальное заполнение меню. Деньги хранятся в копейках.
Проверка: изучить `Schema`, `Open` и `Seed`; в итоговой версии запустить
`go test ./internal/store` для проверки повторного seed и внешних ключей.

Проверка: создать администратора через CLI, зарегистрироваться, выйти и войти;

## 20. `fix: align cup rim with body border box`

Файлы: `internal/web/static/style.css`, `templates/base.html`,
`DEVELOPMENT.md`, `VERIFICATION.md`.
Причина смещения верха: правило `*` не охватывало псевдоэлементы, поэтому
овал `::before` имел внешнюю ширину 158 px (148 + две рамки по 5),
а корпус — 148 px. `border-box` теперь применяется и к псевдоэлементам,
ширина овала определяется краями `left: 0; right: 0` и совпадает с корпусом.
Обновлён параметр CSS для сброса кэша. Бинарник пересобран.

## Как повторить разработку

Начните с простого `main`, затем добавьте схему и подключение базы.
Реализуйте регистрацию и сессии до защищённых страниц. Далее добавляйте CRUD
категорий, CRUD блюд, корзину и только затем транзакцию оформления. Каждую
форму подключайте через CSRF и проверку роли. Сначала проверяйте серверные
ограничения, потом оформление. Не добавляйте реальные базы и пароли в Git.
